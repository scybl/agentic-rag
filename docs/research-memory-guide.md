# 多 Agent 研究、长期记忆与恢复指南

当前研究模式是一套**有预算、能复用、可恢复的小型研究流程**。以下描述实际实现，默认参数和版本号由[代码事实参考](reference.md)维护，运行命令集中在[运行指南](operations.md)。

## 先分清研究记忆和聊天记忆

**当前有独立的会话记忆层。** 交互模式共用 `conversation_id`，原始问答保存到单独的 SQLite；先把追问还原为独立问题，再创建新的 `run_id` 和图 `thread_id`。旧回答用于识别对象，不直接进入本题证据。`session_ledger` 仍只累计用量，不承担聊天记忆。

| 能力 | 当前行为 | 不能混淆为 |
|---|---|---|
| 本次研究的工作状态 | 保存本题的路由、查询历史、证据、评审和重试进度 | 保存用户的历轮对话 |
| 跨研究的资料复用 | 按当前问题召回兼容的新闻阅读笔记，严格键复用已完成任务 | 自动理解“上面第二个事件” |
| 检查点恢复 | `--resume RUN_ID` 继续原任务；完成后只展示旧结果 | 基于旧答案新开一轮追问或刷新新闻 |
| 证据上下文管理 | 选择有限材料、结构化摘录、字符预算、原文回读 | 通用聊天历史摘要或精确整场 Token 预算 |
| 会话上下文管理 | 近期问答、较早抽取摘要、原文核对与编号消解 | 已解决全部指代、自动学习偏好、整场精确 Token 硬预算 |

例如先问“分析比亚迪最近七天的动态”，再问“它的风险呢”，会话层尝试确定“它”指比亚迪并展示还原后的问题；对象不唯一时询问用户。本轮显式日期、数量、阈值不能被改写遗漏；其余语义仍依赖模型，需要观察实际改写。显式新话题或 `/new` 可避免不必要继承。

证据入口：[会话实现](../src/agentic_rag/conversation.py)、[交互提问与恢复](../src/agentic_rag/cli.py)的 `converse` / `run_with_trace`、[状态字段](../src/agentic_rag/graph/state.py)、[资料召回](../src/agentic_rag/research/service.py)的 `recall`。会话压缩和资料阅读是不同层，完整用法见[会话指南](conversation-guide.md)。

## 1. 运行

```bat
conda activate agent
agentic-rag "分析一下2027年猪肉价格走势"
```

在另一台机器或重新安装环境时：

```bat
python -m pip install -e ".[dev]"
```

研究模式默认打开；知识目录的自动监听仍默认关闭。不要把项目说明放进 `knowledge/`，本文件仅供开发者阅读。

## 2. 实际工作顺序

1. CLI 给本次研究创建编号，LangGraph 保存节点检查点。
2. 路由器生成任务类型、数据源和完整新闻查询指令：实际查询组、人物、机构、主题、精确时间/自然日、栏目、指定来源、排序、覆盖、正文预算和核对因素。每个人物/机构必须进入至少一组实际查询，否则反馈具体缺失项；主题是检索线索，程序在四组预算内补充并展示未覆盖项，不再因主题措辞差异阻断研究。另记录估计类型、目标事件和时点，概率问题进入专用规则路径。
3. 选择新闻源且查询计划有效时，长期记忆用关键词索引和向量索引联合召回已读文章，并执行与实时查询相同的精确时间、自然日、栏目和来源硬过滤，再按路由实体词过滤候选。召回不是已确认相关，也不会因为只有猪肉笔记就强制把它用于苹果研究。随后仍检查在线来源。
4. 本地知识、新闻 API、公开搜索并行收集。开放检索先取完匹配摘要页、去重和硬过滤，对全部摘要做向量/词法排序后，每批12篇轻量判断相关性与阅读价值；空摘要保留为待确认。按查询覆盖和阅读价值选择有限核心文章，正文缺失、重复或主题不符时从剩余候选补位。正文核对只看片段，不冒充全文阅读；真正精读仍在第6步。所有候选、初筛理由、补位和最终选择留档。不自动添加日期窗口。

   明确“最新N篇、选M篇”时仍使用独立的限定母集路径：取最新N个不同且实质相关的文章，逐批排除同名词误命中，宏观扩展词和集合外旧记忆不混入母集。显式候选上限200、分析上限100；扫描2000条仍不足则报告失败。“影响最大”使用五维潜在影响评分，不用初筛阅读价值或相似度冒充影响力；该路径不擅自更换排名入选文章。
5. 筛选器先给每篇材料「保留／排除／待确认」和理由，终端与研究事件留痕。历史数据、反向证据不因没有目标年份预测而排除；解析失败暂存待确认，不再默认删除。
6. 默认不超过1200字符的整篇新闻直接保留原文，持久化为 `source_excerpt`，终端明确显示阅读模型调用为0；这不是已完成事实核实。较长新闻由阅读 Agent 按段处理，句子编号回填原文及位置，先去重再限制每次六项。截断允许二分一次。下游根据当前问题选取完整原文句子，不再只依赖可能遗漏限定的六项摘要。简单事实使用短证据核对，分析/预测继续使用完整证据评估与思考。补搜保留旧成果，确定的相关性判断也可复用。

   短文全文保存在库中，最终逐篇清单只展示180字符预算内的完整原句，并标注“原文节选，未独立核实”，不把整篇文章塞进终端表格。这是展示裁剪，不删除持久化原文，也不把截断半句当成完整证据。
7. 核心文章数量有上限，入选文章的阅读分段数量不再设上限：所有分段先持久化入队，然后有界并发执行。未读完时保留节点检查点和已完成成果，恢复时只补缺失部分。调度器根据核对因素，最多取三个目标（且不超过 `SPECIALIST_COUNT`）创建专题 Agent；事实型问题或无入选证据时跳过，专题名额不再与阅读段数竞争。每个专题可以回读一轮、最多两篇已保存原文；返回摘要硬限制500字。专题失败也停在可恢复节点。
8. 普通研究缺失关键事实时追加补搜；已经足以条件分析、查询重复、连续无新增、达到轮次或全局时间/模型调用预算时停止扩张，不再按已经读了多少段阻止补搜。明确限定候选集合的批量任务不自动补搜集合外新闻，缺口保留为限制，避免改变用户要求的比较范围。
9. 证据检查的可用E编号是硬准入条件；过滤后统一重编，丢弃可能混入已排除事实的检查摘要，原始评估另存审计。生成器综合准入证据和专题建议；评审逐项回应C编号风险，数字/单位、预测限定等已知错误模式另由程序检查。实际概率估算仍严格核对数据、方法、事件、时点和引用；询问“这些报道能否支持某概率”属于证据能力核对，允许有依据地回答不支持。不通过则有界重写/补搜，耗尽预算明确失败。

预测可以从当前事实推导，不要求新闻里已经写好未来答案。专题自动补搜会过滤“未来年份 + 预测”这类追逐确定未来数值的请求，并在终端说明；它不会擅自更改用户明确的日期条件。这是启发式护栏，不是完整语义判定器。

## 3. 增强向量数据库怎样存

这里的“增强”是**原文与版本 + 结构化阅读成果 + 混合召回 + 可修复索引**，不是把所有内容塞进一个向量。

| 存储 | 保存什么 | 用途 |
|---|---|---|
| SQLite `research.sqlite3` | 原文版本、片段、引用位置、阅读覆盖率、任务、事件、缓存 | 可靠记录与精确去重的事实源 |
| SQLite FTS5 | 中文双字词与英文关键词倒排索引 | 关键词命中，BM25 排序 |
| Chroma `news_chunks_*` | 原文片段向量及文章/版本/片段编号 | 可重建的原文语义索引；当前回读用原文库定位 |
| Chroma `reading_memory_*` | 阅读事实、观点、原文引用的向量 | 当前长期记忆的主要语义召回入口 |
| Chroma `task_analysis_*` | 专题结论向量、问题、证据哈希、模型版本、运行编号 | 持久化分析投影；当前专题复用走严格任务键，不把相似结论直接当事实 |
| SQLite `checkpoints.sqlite3` | LangGraph 节点状态 | 从未完成节点继续 |
| 原有新闻向量缓存 | 候选标题/摘要向量 | 从本次 API 候选中排序，独立于阅读成果 |
| 原有最终答案缓存 | 已核验答案及证据身份 | 同问题、同实际证据等条件下复用，原有 TTL 仍生效 |

关键词与向量各取有限候选，SQLite 检查当前文章版本与阅读版本，程序校验实体词和日期，再用 RRF 合并排名。实体词采用字面任一匹配，可能漏掉间接驱动，所以不是完美语义过滤；同名实体仍由筛选器辨别。先召回再读取，不为每次问答加载整个文章库。旧版本留档，但不会作为当前版本自动召回。

向量写入与模型阅读解耦：阅读成果和“待同步向量”在同一 SQLite 事务落盘；即使 Chroma 暂时失败，也不必重新调用模型。修复命令只重建投影。

## 4. 怎样认定“已经分析过”

不能靠标题相同或语义相似来判断。

- **文章身份**：数据源 + API 文章 ID（缺失时使用 URL/来源标识）。同标题、不同 ID 不自动合并。
- **摘要筛选缓存**：筛选规则 + 模型版本 + 当前问题 + 文章身份 + 摘要内容；正文主题核对还绑定完整正文。问题、材料或模型变化会重新筛选。初筛只是阅读决定，不是已经分析或核实的事实。
- **内容版本**：规范化正文 + 标题、发布时间、材料类型、来源，计算 SHA-256。只清理格式，不删除数字和单位。
- **阅读版本**：阅读规则版本 + Ollama 实际模型摘要及生成设置（包括思考开关）+ 分段长度 + 短文原样保留阈值。改动会生成新配方，不把旧成果伪装成新配置产物。
- **片段任务键**：文章身份 + 头信息 + 当前片段正文哈希 + 阅读版本 + 本篇是否走原样保留路径。
- **专题任务键**：目标 + 原始问题 + 实际证据上下文 + 原文版本 + 模型版本 + 规则版本 + 当天日期。

全部片段都完成，才记作 `complete`；部分完成是 `partial`。完整表示“所有片段已按流程处理”，**不代表模型提取了原文所有信息，也不代表报道事实已经独立核实**。

阅读成果同时保存原文阶段/情景背景。笔记用于持久化检索与复用，生成上下文优先从对应原文按本题选择完整句子；长句容不下会明确要求回读，不裁成半个数字或删掉“预计”，也不用发布时间补事件时间。旧的无原文附带对象仍按完整事实块选择。明确批量任务保留全部入选文章并附逐篇影响/阅读清单，不被默认9条证据上限静默截断。候选数、分析数、全文标识、阅读完成率与专题执行有硬检查，不满足就标记未完成。没有量化估值模型时只给方向与条件，不把历史/机构区间搬成目标年份价格；规则仍不能证明所有自然语言推断正确。

专题总结也是待检查的模型输出，不是新增事实。生成前对其价格数字和事件月份做检查，失败句子不再传入生成器，但原始专题成果继续保存，并在终端说明过滤原因。金额区间要检查两端，不能只检查靠近“美元”的一个数字；机构目标区间不能充当本研究估值，内部C编号也不能成为最终来源引用。修正要求在生成提示末尾再次明确，以减少长上下文中的忽略。

专题与最终反思显式接收当前研究日期：过去月份的预测只能标为当时观点，不能直接列作未来事件。原文摘句时，邻近事件月份/情景标题与句子作为一个块保留。另有窄范围的倍数检查拦截“1.2亿到6亿就是翻倍”等显著矛盾；它不是通用统计计算器。已明确数字为预计值时，允许用它做有标识的算术核对，不能反而把正确的5倍/400%说明当成事实化错误。

正文变动会产生新版本；分段边界未变且内容相同的片段仍可复用。插入内容导致后续分段边界变化时，可能重读多个片段，这是当前按字符分段方案的边界。

更换阅读提示词/模型，需要新阅读成果；更换嵌入模型，只需重建向量，不需要重新阅读。嵌入命名空间按配置名称区分：如果本地同一路径的嵌入权重原地替换，请换一个版本化路径/名称，系统不会自动识别权重文件变化。

## 5. 并发是真实的，但有上限

默认值在 `.env.example`；已有 `.env` 未填写时自动使用默认值。

| 配置 | 默认值 | 含义 |
|---|---:|---|
| `AGENT_WORKERS` | 4 | 每批最多同时工作的子任务 |
| `LLM_CONCURRENCY` | 2 | 进程内最多两个模型请求在途 |
| `IO_CONCURRENCY` | 4 | 进程内受控网络调用上限 |
| `SPECIALIST_COUNT` | 3 | 每轮专题目标数上限 |
| `RESEARCH_MAX_TASKS` | 20 | 兼容通用调度器；主研究阅读/专题队列不使用数量截断 |
| `RESEARCH_HARD_MAX_TASKS` | 200 | 兼容旧配置，当前主研究不再使用 |
| `RESEARCH_MAX_ROUNDS` | 3 | 补搜轮数上限；不包含初次抓取 |
| `TASK_MAX_ATTEMPTS` | 2 | 子任务失败尝试上限；底层模型请求重试另有配置 |
| `LLM_REQUEST_TIMEOUT` | 120 | 单次模型 HTTP 请求超时秒数 |
| `RESEARCH_TIMEOUT` | 900 | 一批子任务的调度时间预算，不是端到端超时 |
| `RESEARCH_TOTAL_TIMEOUT` | 1800 | 本研究累计执行时间的协作式截止；恢复不计离线等待，0关闭 |
| `RESEARCH_MAX_MODEL_CALLS` | 160 | 累计真实调用上限，含失败重试，0关闭 |
| `READING_CHUNK_CHARS` | 2200 | 一次独立阅读的片段字符数 |
| `READING_VERBATIM_MAX_CHARS` | 1200 | 整篇不超过此长度时原样保留，不调用阅读模型；0关闭 |

本轮预算耗尽时停止派发，保留检查点；不会把共享阅读任务标为永久错误，后续提高预算可继续。预算是应用的协作式停止，不保证远端推理立即取消，也不是精确Token硬限额。任务的永久内容/结构错误仍须按失败类型处理，不能无限自动重试。
| `MEMORY_RECALL_K` | 3 | 长期记忆补充召回篇数 |

“一个 Agent”在这里是一个有目标、输入、模型调用和持久结果的逻辑任务，不是为每条新闻无限新建操作系统线程。LangGraph 负责阶段编排，Python 线程池负责子任务并行，SQLite 负责去重领取与恢复。

模型槽位与工作线程分离：四个任务中可以有两个在请求模型，其余等待或做其他工作。终端显示的是应用的在途请求数，**不保证 Ollama/GPU 内部真的同时推理两个请求**。如果显存不足或吞吐下降，将 `LLM_CONCURRENCY=1`；并行检索和任务调度仍保留。

若希望两个模型请求真正并行，Ollama 服务端也需在启动前设置 `OLLAMA_NUM_PARALLEL=2`；runner 的 `-np 2` 才是运行时证据。Flash Attention 与 `q8_0` KV cache 可降低双上下文的显存开销，但不会减少模型权重本身，修改服务环境后必须重启 Ollama。短结构化节点还会采用阶段预算并关闭思考，把有限算力留给证据综合、专题推断和最终回答。

并发上限是单进程的；两个 CLI 进程不会共享同一模型信号量。但它们会通过同一 SQLite 原子任务键避免重复计算相同子任务。同一个研究编号不能同时恢复。

## 6. 中断、重试与检查成果

每次启动会显示真实研究编号，下面的 `RUN_ID` / `READING_ID` 要替换成终端里的值。

```bat
agentic-rag --runs
agentic-rag --status RUN_ID
agentic-rag --resume RUN_ID
agentic-rag --resume RUN_ID --retry-failed
agentic-rag --inspect-reading READING_ID
agentic-rag --repair-memory
```

- `--runs` / `--status` / `--inspect-reading` 不调用对话模型。
- `--status` 默认是核心数字与停止原因，加 `-v` 查看完整 JSON。中断时已保存节点结果仍可能需要推进，不能仅用“next 为空”判定研究结束；恢复会复用已写入的节点结果。
- `--resume` 使用原检查点；没有待推进工作且已有答案时离线展示，不连接模型、不启动监听、不改写研究事件。已有草稿但有待执行任务不算结束，显式 `--retry-failed` 仍走执行流程。它不是刷新新闻的命令，要新资料请发起新问题。
- `--retry-failed` 重置失败任务的尝试预算，从保存材料重新进入筛选、阅读阶段；兼容的已完成任务继续复用。
- `--repair-memory` 补齐所有待写向量；遇到错误停止，阅读记录不丢失。它可能加载嵌入模型，但不调用对话模型。
- 修改模型、阅读规则或工作流版本后，不继续混用未完成的旧检查点；发起新研究。已完成旧研究仍能展示。

Ctrl+C 是协作取消：停止追加任务，撤销当前执行者提交权限；已经发出去的 HTTP 请求可能到超时才退出。**不能安全地强杀任意 Python 线程**。异常进程退出后，运行锁约45秒、任务租约默认180秒会到期；不要通过删除数据库来“解锁”。

保存的事件是可核对的任务状态、目标、完整新闻查询指令、分页、候选/过滤/入选数量、来源、引用、错误和结论摘要，不是模型隐藏的逐字思维链。`agentic-rag --status RUN_ID -v` 的 `news_candidates` 事件保存本次全部匹配候选的标题/摘要、元数据、排名、评分分量与系数、正文选择状态；未入选为暂未精读，不表示无关。`news_ranked` 记录分页是否完成与暂未精读数量，工具调用编号区分不同检索批次。默认状态只显示数量摘要。

研究事件同时保存每次对话模型调用的 token 计量（`kind=token_usage`），包含阶段、调用 ID、任务 ID/尝试号、输入/生成计数、已提供的细分及状态，不额外保存提示、回答或思考正文。每个并发工作线程继承当前问题与阶段上下文；同一任务的多次真实调用分别累计，复用任务不重新计量。`--status RUN_ID` 读取全量账本，`--resume` 区分新增和历史；旧版本没有记录的历史不能补算。详见[统计口径与限制](operations.md#token-统计怎么看)。

## 7. 学习代码的顺序

1. `cli.py`：从接收问题、分配运行编号到输出事件。
2. `graph/build.py`：主图如何接入召回、阅读和专题调度。
3. `research/service.py`：怎样把问题拆成任务、生成任务键、复用成果和回读原文。
4. `research/scheduler.py`：任务排队、依赖、原子领取、租约、重试与取消。
5. `research/store.py`：文章身份/版本、引用位置、事务与索引待办。
6. `research/memory.py`：Chroma 投影、FTS5 + 向量的混合召回。
7. `research/chains.py`：阅读及专题 Agent 的结构化输出规则。
8. `research/runtime.py` / `research/session.py`：资源槽位与运行互斥。
9. `token_usage.py`：模型回调计量、并发归属、事件重放与终端汇总。

工具层改造后，还可读[工具层的边界与实际调用](tools-guide.md)。知识、新闻、公开搜索与已保存新闻回读已接入四个真实 `@tool`；`research/service.py` 保留调度与成果管理，不再直接实现原文片段选择。`agentic-rag --list-tools` 可在不调用模型、不初始化研究数据库时查看工具契约。

此外四项规则工具统一处理输出结构、自适应重试和概率契约。它们执行确定性检查，不是四个额外模型 Agent。模型尝试、子任务尝试、补搜轮数和答案重写各有计数，不能把其中一个上限当整场总调用上限。

### 流程图对应关系

[当前研究流程 SVG](agentic-rag-research-flow.svg)是纵向8步总览，评估与专题分析合并展示，详细边见 `graph/build.py`：

1. CLI 接收问题或恢复研究 → 问题与研究编号。
2. 路由器规划数据源与查询条件 → 来源、查询词与日期。
3. 取证工具并行收集，新闻全分页、排序并限量取正文 → 去重后的材料与候选留档。
4. 筛选器先筛材料，阅读 Agent 按段保存 → 可追溯的阅读成果。
5. 研究 Agent 核对缺口并专题分析，概率题执行证据契约 → 证据可用则生成；缺事实且有预算则补搜。
6. 生成器综合证据 → 候选答案与引用。
7. 评审器核对风险与任务，概率题执行答案契约 → 通过则交付；预算内补搜/重写；耗尽预算则交付限制说明。
8. CLI 展示结果及用量/耗时 → 用户收到核验结果或未完成说明。

已知边界：

统一问题清单见[当前状态](status.md)，包含尚未修复的数字/单位校验、错误分类、专题长度约束和记忆审核问题；不能因已有原文引用而声称完整事实核验。

- 新闻阅读仅处理本次入选及记忆召回文章；不会预先分析远端所有新闻。
- 网页来源仍是公开搜索摘要，未加入通用网页全文爬虫。摘要不能冒充完整研报。
- 当前混合召回在有限候选后做日期过滤，严格日期范围可能召回较少；不是全库高召回率保证。
- 模型评审可能漏掉价格口径混淆、因果推导错误；通过自动核验不等于预测正确。需要更完善的领域标注评估集与人工复核。
- 文章版本、检查点、事件会增长；当前没有自动清理，避免开发期丢记录。规模上升后需要归档与容量治理。
- 当前是本地单用户演示架构，不是分布式生产调度平台；不保证外部模型调用严格只发生一次。进程崩溃在“模型已返回、尚未保存”的缝隙中，允许重试计算，但拒绝过期执行者覆盖结果。
- 数据位于 `.chroma/`，包含新闻原文、问题和分析成果，请按私有数据保护；不要提交到 Git。
