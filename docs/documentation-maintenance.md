# 文档维护约定

目标是让代码变化触发可见检查，而不是承诺机器能自动理解并证明全部中文解释。当前采用“代码事实自动生成 + 解释人工审阅 + 未审阅变更门禁”。

## 一次改代码后的正常流程

```bat
python scripts\docs_sync.py --check
python scripts\docs_sync.py --refresh
```

第一步只读，列出未确认变动；第二步机械更新 `reference.md` 和公开 HTML 的代码定位，不替你改写设计解释，也不会确认已审阅。

按变动核对 README、相关专题、两图和已知问题。修复了问题就同步移出未修列表；不能只改状态标题。个人面试资料不属于公开文档，不由该脚本读取或改写。

完成审阅后：

```bat
python scripts\docs_sync.py --acknowledge-review
python scripts\docs_sync.py --check
python -m pytest -q
```

`--acknowledge-review` 是维护者的明确确认：仅在生成参考、链接和代码定位有效时记录源码与文档指纹；它不代替测试、不证明语义正确、不自动运行模型。不要为消除红灯而盲目执行。

## 什么由程序维护

- 配置代码的默认表达式、模板示例和兼容旧变量名；不读取本机 `.env`。
- Python 命令参数、工具输入声明、工具装饰器、版本常量和 LangGraph 两种模式的边。
- HTML 中代码符号对应的行号。
- Markdown/HTML 本地链接存在性、HTML 内部锚点、SVG XML 和基本布局约束；公开页面不能链接到未发布的个人面试资料。
- 源码、测试、评估、配置、脚本、CI 及项目说明的新增/修改/删除指纹；LF/CRLF 不产生伪变更。

检查只使用 Python 标准库，不安装运行依赖、不连接模型或新闻 API、不修改数据库。生成代码参考采用 AST 读取而非导入业务模块，避免加载个人配置或模型。

## 谁来维护解释

| 改动位置 | 必须重点审阅 |
|---|---|
| CLI / 配置 / 打包 | README、运行指南、代码参考、其他提到默认值的说明 |
| 图、节点、提示词 | 技术详解、两张 SVG、预测说明、模式说明 |
| tools | 工具指南、技术详解、流程图、状态页 |
| research | 研究指南、技术详解、状态页、流程图 |
| ingestion / 新闻检索 | 运行指南、RAG 基础、技术详解、研究指南 |
| evaluation / tests | 评估说明、状态页、对应能力的验证范围 |

门禁对上述范围采取保守策略：源码变化即要求确认所有受维护说明是否仍适用，哪怕最终不需要改每个文件。新增说明自动纳入；`knowledge/` 是业务证据，不被改写或当作项目解释。

## 个人资料、项目规划与公开仓库分离

`.gitignore` 排除路径名包含“面试”、“简历”或 `interview`（大小写不敏感）的文件及目录；另排除 `docs/炫技增强技术设计.md`、规划/roadmap Markdown、`docs/plans/`、`docs/planning/` 及文档目录中的 Word/PDF 私有材料。文档门禁在读取前采用对应规则排除，发布脚本也禁止打包这些文件。资料存在、修改或缺失都不影响公开检查，`--refresh` 不会改写它们，审阅记录不保存其内容指纹。

已经被 Git 追踪的文件仅添加 ignore 不够，需要针对明确文件执行 `git rm --cached -- "文件路径"`，再提交。这只取消后续版本的追踪，本地文件仍在；旧 Git 历史中的内容仍可检索。本项目本次不改写历史、不强制推送。

不要把私有资料或项目规划的链接留在公开 README/导航中。临时导入目录 `rag_copy_staging/` 及接收辅助文件 `.rag-copy-receiver.mjs` 也不上传。若以后用其他名称保存私有资料，应同时补充忽略规则、文档枚举规则及发布过滤规则。验证时应检查不带本地资料的提交快照，确保 GitHub CI 与本机一致。

## CI 与本地检查

pytest 的文档测试检查当前工作区。另有 `.github/workflows/docs.yml`，push / pull request 时仅用标准库执行文档检查，不下载模型。工作流只是仓库配置；是否能阻止合并，仍需仓库管理员在分支保护中要求该检查通过，本次没有修改远端设置。

## 不要制造另一种文档漂移

- 不在多处写“本次最新通过 N 项”；看实际测试输出，旧记录标明历史。
- 不把本机模型名当仓库默认值，不复制 `.env` 或认证信息。
- SVG 是学习阶段概览，不能用简化图冒充精确节点拓扑；精确连接看自动参考。
- 文档能说明未实现方案，但必须写“建议/待实现”。
- 检查无法验证外链长期可用、自然语言结论、真实性能、模型质量或截图视觉质量；这些仍需相应实测与人工复核。
