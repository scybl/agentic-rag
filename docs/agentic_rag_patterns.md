# 智能体 RAG 模式

智能体 RAG 用一个能在每个步骤做出决策的智能体，取代固定的“先检索、后生成”流程。它会判断去哪里查找信息、检索到的证据是否足够，以及自己的回答是否可信。LangGraph 等框架将这种过程建模成状态机，其中节点代表操作，边代表决策。

## 自适应路由

路由器检查收到的问题，并将其发送给最合适的数据源：领域文档类问题使用向量数据库，结构化或数值类问题使用 SQL 数据库，近期事件类问题使用网络搜索。路由通常由一次小型大语言模型调用实现，其返回值是受可用数据源约束的结构化输出。良好的路由能够避免把检索资源浪费在不可能包含答案的数据源上。

## 检索结果评估

完成检索后，评估器大语言模型会检查每一个检索到的文本块，并通过二元的是/否判断来评估它与问题的相关性。在生成回答前丢弃无关文本块，可以减少上下文稀释和幻觉。如果没有任何文本块通过评估，系统就能明确知道检索失败，并采取应对措施，而不是生成质量低下的回答。

## 查询改写与自我纠正

检索失败时，智能体系统会改写查询——展开缩写、添加同义词、明确表达意图——然后重试。这个过程称为查询改写或查询转换。系统通常会限制改写次数（例如最多重试两次），随后回退到网络搜索等替代数据源，确保循环一定能够终止。

## 幻觉检查

完成生成后，评估器会把回答与检索到的证据进行比较，验证每项陈述都有依据。如果回答缺乏依据，系统可以重新生成、改写查询以寻找更好的证据，或者诚实地回答“我不知道”。这种生成后检查正是自我纠正型 RAG 与标准流程之间的区别：系统会先评估自己的输出，再向用户展示。

## 成本权衡

每一步评估都需要额外调用一次大语言模型，因而会增加延迟——在 CPU 推理场景中尤其明显。实际系统需要选择最重要的检查：文档评估和幻觉检查通常能在每次调用中提供最高价值，而在对延迟敏感的部署中，往往会省略单独的回答实用性评估。
