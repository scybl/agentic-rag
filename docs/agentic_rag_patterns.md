# 智能体 RAG 模式与本项目的对应关系

本文区分设计模式与已实现能力。精确节点边表见[代码事实参考](reference.md)，完整解释见[技术详解](技术细节详解.md)。

| 模式 | 本项目怎么做 | 不要误解成 |
|---|---|---|
| 自适应路由 | 一次规划，可同时选知识、新闻、网络 | 只能三选一，或已接任意 SQL |
| 受控工具 | 四项取证 + 四项规则 `@tool`，Schema、ToolMessage、完整 artifact、事件 | 模型原生 tool_calls 的自由 ReAct |
| 两阶段新闻检索 | 全分页收集匹配摘要，统一评分留档，只获取预算内正文 | 全部候选都已读过，或评分等于新闻热度 |
| 模型自适应 | 输出先校验，按失败类别有限调整参数/反馈/切分 | 所有错误原样重试、无限扩容 |
| 概率约束 | 生成前核对直接数据与方法，交付前检查事件/时点/引用 | 自动计算市场概率、规则通过等于数值真实 |
| 检索纠错 | 单篇相关性与整批充分性分开，按缺口补搜 | 只有零结果才重试 |
| 自我修正 | 依据和任务完成双检查，区分补事实与重写 | 评审能证明事实正确 |
| 多 Agent | 阅读/专题是持久任务，有限线程池 | 每条新闻无限开线程，或每个节点都是 Agent |
| 长期记忆 | 内容版本、阅读配方、精确引用、混合召回和投影修复 | 语义相似就复用结论 |
| 恢复 | CLI 检查点 + 任务记录，兼容版本检查 next/tasks 后继续 | 下一次问题自动有聊天上下文 |
| 可观测性 | 步骤/调用/任务账本、已知 token 与墙钟时间、精简/详细视图 | 思考文本即解释、缺失计量当作零 |

## 为什么不把全部自主权交给模型

模型提出数据源、因素、补搜词和修订建议；程序负责白名单、校验、预算、状态分支与落盘。这样能分层测试、解释故障。更自由的工具循环是可选演进，不是当前能力。

## 补搜不改变用户问题

原问题一直保留。初次路由之后，充分性评估、专题或最终评审提出定向查询；同一新闻/网络工具执行，保留旧证据及日期条件，再筛选，研究模式随后精读。不重新路由整个问题，也不保证补搜一定找到资料。

研究与基础模式的轮次预算不同；重复查询、无新增、任务上限也限制扩张，重写独立计数。具体值见[默认配置](reference.md)。

## 并发与效果取舍

独立来源、入选新闻正文、阅读/专题任务可分别并行；路由、筛选、生成和评审不是统统并行。模型槽位与线程数分开，应用并发不保证 GPU 同时推理。

阅读复用减少重复工作，但不能省掉实时取证和质量核对。更多 Agent 不自动提升效果，会增加延迟、资源消耗和错误传播。业务质量需要标注集和延迟测量，当前没有充分 A/B 证据。
