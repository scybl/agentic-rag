# 会话记忆与上下文压缩

交互式 CLI 已接入连续问答。会话层先解析“它”“刚才第二条”等指代，再启动全新的研究；历史回答只帮助确定对象，不成为新闻证据。长会话使用可回查的抽取式压缩，不生成新的“记忆事实”。这是面向本地展示的受控实现，不保证任意语言指代、全部语义约束或事实判断正确。

## 怎么使用

启动 `agentic-rag`，终端会显示会话编号。示例交互：

```text
> 分析比亚迪最近七天的动态，按明确的数字编号列出事件
> 它的主要风险是什么？
> /history
> /turn 1
> 第1轮的第二条具体有什么影响？
> /new
> 解释黄金与实际利率的关系
```

“刚才第二条”指最近一轮答案；如果已经问过风险，再想回到第一轮清单，应明确“第1轮的第二条”。编号需要原回答中的明确数字列表；多个章节重复编号、表格行、中文编号或无序列表不能唯一确定时会要求提供条目名称。

| 操作 | 行为 |
|---|---|
| `agentic-rag --conversation demo` | 建立或接续名为 demo 的会话，支持跨进程继续 |
| `agentic-rag --conversation demo "它的风险呢"` | 单次命令也承接指定会话 |
| `agentic-rag "完整问题"` | 默认单次独立研究，不隐式读其他会话 |
| `agentic-rag --no-conversation` | 禁用聊天记忆，交互每题独立 |
| `/new` | 新会话编号，不删除旧记录，不再注入旧会话 |
| `/history` | 当前会话最近20轮的编号、状态、问题和运行编号 |
| `/turn N` | 只读展示第N轮的完整原文与消解审计，不调用模型 |
| `--resume RUN_ID` | 恢复原研究，不是提交新一轮问题；不能同时指定会话 |

无需安装新依赖或重建知识索引；重启已有可编辑安装的 CLI 即可。默认会话库 `.chroma/conversations.sqlite3` 只在本机保存；不要提交或公开包含私人问题的数据库。若把 Ollama 地址改为远程，消解使用的历史片段也会发送给该模型服务。

## 为什么不直接共用图线程

```text
conversation_id → 会话原始问答、修订号、压缩视图
                       ↓ 追问消解或澄清
                   独立完整问题
                       ↓
run_id = 图 thread_id → 本题路由、证据、任务、核验与恢复
```

现有研究图不是聊天消息图。直接共享图线程会留下上一题的完成状态、证据和任务计划，因此在图外增加会话协调层，而非修改整个研究图拓扑。首次完整提问无需消解模型；后续至多一次消解模型尝试，截断、格式或请求失败便提示澄清，不追加纠错文本或扩充输出突破已装箱的首轮预算。研究内部其他阶段的有界重试策略不变。

会话返回 `independent` 时程序使用原始用户文本，不接受模型对独立问题的多余改写。`followup` 必须提供完整问题和引用：轮次、字段、逐字摘录。程序核对原文，最近指代必须关联最近轮，序数必须匹配唯一原始编号，本轮显式数字条件不得遗漏。失败返回 `clarify`，不启动研究。明确“换个话题”可走独立分支；`/new` 是更彻底的会话隔离。

图保存 `user_question`、`conversation_id`、`conversation_revision`、`conversation_resolution`，便于回查；`question` / `original_question` 在研究内部表示消解后的研究目标。历史回答不放入 `documents` 或 `evidence_context`，新研究仍必须独立取证和核验。

## 压缩算法与预算

采用 SQLite 原文 + 动态抽取投影，不安装通用记忆框架，也不额外调用模型总结。已有 Pydantic、LangChain 模型封装与标准库足以实现这一层；自研范围仅是项目特定的隔离、引用验证、预算和提交协议。

1. 读取当前会话一致快照，默认最多最近100轮；显式“第N轮”可单独读取更早原文。
2. 最近 `CONVERSATION_RECENT_TURNS` 轮优先保留完整问答，较早轮提取完整行句，优先保留标题、数字列表和用户问题。摘要不比原文短时使用原文。
3. 按从新到旧的优先级装箱，再恢复时序。完整记录装不下就尝试摘要；仍不够则省略该轮并计数。不切半个 JSON、数字或事实句。
4. 保存原问题、还原问题、答案和时间戳，摘要不会覆盖原文；实际引用需要在原文上逐字校验。压缩丢失的细节可用 `/turn N` 查看后明确追问，不让模型补造。
5. 显示实际装入字节数、摘要轮数、省略轮数；审计还记录扫描原文大小。摘要、查表与装箱本身无 LLM 调用。

预算是序列化 JSON 的 **UTF-8 字节**。当前容量取配置上限与“上下文窗口扣除首轮输出额度、系统说明、Schema 和模板余量”的较小值；把字节作为保守的输入代理，不宣称等于模型 tokenizer。问题本身超预算直接提示缩短，不截断用户输入。

| 配置 | 默认 | 含义 |
|---|---|---|
| `CONVERSATION_DB` | `.chroma/conversations.sqlite3` | 独立会话库 |
| `CONVERSATION_CONTEXT_BYTES` | 12000 | 消解输入 JSON 的字节上限，还受模型窗口约束 |
| `CONVERSATION_RECENT_TURNS` | 3 | 近期原文优先保留轮数，0 表示全部允许压缩 |

这不是整场研究的精确 Token 硬预算，也没有统一限制所有阅读、专题、重试与生成消耗。实际用量以 Ollama 返回的计数为准；会话消解单列记录，CLI 程序总账包含它，研究运行总账不包含图外消解。未知用量不能当成零。

## 持久化与并发

每轮保存原始输入、独立问题、回答、状态、消解决策、原文引用、上下文计量和消解用量。`complete` 与 `needs_attention` 分开；澄清单独标记 `clarification`，下一轮可补全未解决的问题。执行异常不把半截回答写入会话。

写入使用 SQLite `BEGIN IMMEDIATE` 和修订号比较更新；另一个进程先提交后，本请求拒绝把过时上下文的结果混入历史。运行编号唯一约束使重复提交幂等。冲突或写入失败不会再次执行研究，会明确提示未保存；这不等于多用户访问控制。

已知限制：图检查点、研究库与会话库没有跨库原子提交。正常研究返回后才追加会话；进程恰在其间退出、通过 `--resume` 恢复或只读展示的结果不自动补写聊天。当前需根据保存结果重新明确提问，不能声称具备完整对话崩溃恢复协议。

## 怎么验证和演示

确定性测试覆盖首次独立提问、原文引用伪造、序数错位、旧话题污染、明确日期遗漏、压缩上限、整句保留、早期原文回读、持久化重开、并发冲突、重复提交、澄清不运行图、干净图状态和故障不写入。

```bat
python -m pytest tests/test_conversation.py -q
python scripts/conversation_smoke.py --output .chroma/conversation-smoke.json
```

第二条命令显式调用本机配置的真实模型，但只测试合成会话，不检索财经新闻。2026-10-01 的 `gemma4:26b` 冒烟覆盖代词、编号、换题、压缩后编号、明确年份与双实体歧义。初次发现模型包含“2.”的合法引用被误拦截，修复后重跑；每次结果保留模式、还原问题、用量和耗时。少量开发样本不是大规模指代准确率，也不是端到端投研质量证明。

### 首版验收记录

2026-10-01 上一轮实现验收记录：40项会话回归、全库428项测试及5项子测试通过；本机6类合成会话冒烟均通过。本次文档更新只核查既有结果，没有重新执行模型研究。以上是该版本的历史快照，不承诺未来修改后仍通过；重新验证使用上面的命令。

本机报告位于 `.chroma/conversation-smoke.json`，由脚本重跑覆盖，不属于公开仓库交付。模型已加载时，6个样例的消解耗时为2.62–3.39秒。长历史样例扫描原记录12048字节，包含当前问题的最终消解输入568字节；这是带重复背景的构造样例，两个计数的内容范围也不同，不当作通用压缩率。普通完整首问无需消解模型；上述几秒不包含取证、阅读、生成或核验，真实研究耗时见[状态页](status.md#真实研究耗时样例)。

剩余风险包括中文/嵌套编号支持有限、摘要可能省略关键约束、模型可能错误还原语义或受历史文本诱导。没有生成式滚动摘要、用户偏好抽取、所有否定约束的形式化验证、完整防提示注入或精确整场 Token 准入控制。面试时讲清取舍和失败行为，比声称“无限上下文、完美记忆”更可信。
