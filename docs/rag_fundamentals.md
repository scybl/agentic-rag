# RAG 基础

检索增强生成（Retrieval-Augmented Generation，RAG）是一种利用外部知识为大语言模型回答提供依据的技术。RAG 系统不会只依赖模型在训练期间记住的内容，而是先从知识库中检索相关文档，再要求模型利用这些证据回答问题。

## 基本流程

经典的 RAG 流程包含三个阶段：

1. **摄取**：将文档拆分成文本块，使用嵌入模型转换成向量嵌入，然后存入 Chroma 或 Qdrant 等向量数据库。
2. **检索**：收到问题时，使用同一个模型将用户查询转换成向量，并取回最相似的文本块（通常采用 top-k 相似度搜索）。
3. **生成**：把检索到的文本块作为上下文注入提示词，让大语言模型基于这些内容生成回答。

## 文本分块

分块策略会显著影响检索质量。文本块太小会丢失上下文；文本块太大则会稀释相关信号，并浪费模型的上下文窗口。常见的起点是每块 500～1000 个字符，并保留 10%～20% 的重叠，使在边界处被截断的句子仍能在其中一个文本块中完整出现。大多数框架默认采用递归字符分割：先尝试按段落断开，再按句子断开，最后按单词断开。

## 为什么选择 RAG 而不是微调

当知识频繁变化、必须引用信息来源，或者出于隐私原因不能把数据写入模型权重时，通常优先选择 RAG，而不是微调。更新 RAG 系统只需重新索引文档，一般几分钟即可完成；微调则需要重新训练并进行细致评估。这两种技术可以互补：微调塑造模型的行为和风格，RAG 则提供最新知识。

## 已知的失败模式

RAG 最常见的失败模式包括：检索遗漏（相关文本块没有进入 top-k 结果）、上下文稀释（相关与无关文本块混杂在一起），以及幻觉（模型依靠参数记忆回答，忽略检索到的证据或与之矛盾）。高级 RAG 架构会针对每一种失败模式加入明确的防护机制。
