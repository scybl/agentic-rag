# RAG 基础：对照本项目理解

本文讲概念；实际命令和参数见[代码事实参考](reference.md)，学习顺序见[文档首页](index.md)。

## 三件不同的事

1. **嵌入模型**把文字转换成向量，便于比较语义接近程度，不生成最终答案。
2. **向量数据库**保存向量、文本和元数据，支持近邻检索。本项目用 Chroma。
3. **对话模型**读取问题与证据，生成回答。本项目经 Ollama 调用配置的模型。

RAG 是先找资料再回答，不是把文档训练进模型权重。相似不等于真实，也不保证覆盖全部关键因素。

## 从知识文件到回答

把方法资料放进 `knowledge/`，运行 `python -m agentic_rag.ingestion`。程序扫描 Markdown、TXT、PDF，分块、嵌入并保存知识索引。切块常量见[代码参考](reference.md)；字符数不等于 token 数，效果需用实际检索验证。

路由选择知识源后，`search_knowledge` 将查询交给 Retriever，取回 Top-K 文本块。相关性、充分性和上下文预算进一步决定最终送入模型的片段；不是所有检索结果都参与回答。

## 文件变动需要全部重建吗

通常不用。再次运行摄取命令会增量处理新增、修改和删除，未变文件跳过。显式重建或索引签名/一致性条件触发时才重建。

监听默认关闭。仅重启问答程序不会自动更新非空索引；开发阶段手动增量同步即可。有需要再开启 `--watch` 或后台监听，见[运行指南](operations.md)。耗时取决于文件量、模型和硬件，不承诺固定分钟数。

## 新闻为什么不用预建全库

开放新闻检索先按关键词及明确的日期、栏目条件取完所有匹配摘要页，再去重、硬过滤和语义/词法排序；每批12篇做轻量摘要筛选，再选有限核心正文，缺失、重复或跑题则从候选补位。完整候选、筛选及权重留档，预算外未入选不代表无关。全部入选分段进入持久化阅读队列，不再按总任务数截断。研究模式保存正文及成果，它与稳定知识索引不同，见[研究指南](research-memory-guide.md)。

这里有三层不同结果：候选摘要、入选正文、分段阅读成果。候选多不代表全文读得多；正文抓取成功也不代表所有片段已完成分析。默认日志分别展示候选数、正文预算入选数和阅读覆盖率，历史事件保留评分及选择状态。

`docs/` 的项目说明不参与默认检索；数据源介绍仅说明能力，不是新闻事实。

## 能解决什么，不能保证什么

RAG 方便更新知识、附带来源、控制上下文。微调主要改变模型行为，两者能互补，但本项目没有微调链路。

检索遗漏、过时资料、摘要缺信息、引用错配和推断错误仍可能发生。工作流通过检查和有限修正降低风险，不把核验通过当作事实正确证明。
