# 技术细节详解：从代码理解当前架构

本文描述当前工作区实现，不是早期版本说明。默认开启持久化研究模式；命令、默认值、版本号和完整节点连接见自动生成的[代码事实参考](reference.md)。学习导航见[文档首页](index.md)。

## 1. 一句话介绍

这是一个使用本机 Ollama 的多源证据研究工作流：模型规划要查什么，程序调用受约束的工具；阅读任务保存可追溯成果，专题任务分析不同因素；资料不足就有限补搜，答案不合格就有限重写。

工程价值不是框架名，而是**有状态、有预算、可复用、能追溯、有失败出口**。当前没有网页前端、任意 SQL 查询工具、自由 ReAct Agent 或分布式调度平台。

| 工具 | Schema 校验、ToolCall / ToolMessage、证据与事件 | [工具目录](../src/agentic_rag/tools/__init__.py)、[工具说明](tools-guide.md) |

| 观测与恢复诊断 | 调用/步骤/会话账本、精简视图、只读检查点 | [token_usage.py](../src/agentic_rag/token_usage.py)、[inspection.py](../src/agentic_rag/research/inspection.py) |

LangChain 组织节点内部的 Prompt、模型和工具协议；LangGraph 管节点之间的状态转移。`@tool` 不意味着模型直接自由调用函数：当前模型生成 `SourcePlan`，节点把它翻译成工具参数。

### 框架能力与项目边界

| 问题 | 当前采用 | 原因 |
|---|---|---|
| 状态流转、条件分支、恢复 | LangGraph `StateGraph` + checkpointer | 图和恢复语义由框架维护，节点只返回局部状态更新 |
| Ollama 结构化输出 | `ChatOllama.with_structured_output(..., method="json_schema")` | 让 Ollama 原生 JSON Schema、Pydantic 校验和失败反馈形成同一条链 |
| 同构的正文读取、文档评分 | LangChain `Runnable.batch` + `max_concurrency` | 框架统一管理并发、输入顺序、逐项异常和每项运行配置 |
| 来源收集 | 项目事件队列 + 有限线程池 | 工具执行期间必须实时把“谁调用、为何调用、参数与结果”送回主图；只取批处理最终结果会延迟这些事件 |
| 阅读/专题任务 | 持久化调度器 | 除并发外还需要依赖、原子领取、租约续期、跨运行复用、取消和过期结果保护，普通 `Runnable.batch` 不提供这些语义 |
| 工具调度 | 结构化计划 + 程序调用 `BaseTool` | 工具不是模型自由选择的 ReAct 循环；`ToolNode` 适合执行模型生成的 tool calls，不能替代这里的来源白名单和审计上下文 |

原则是让框架承接它已经定义好的通用语义，不为“框架化”牺牲项目现有的可恢复性、实时审计或确定性。LangGraph 节点级重试也只适合可安全重放的节点；整个取证节点可能产生网络调用、数据库写入和费用，因此不能无条件重跑。模型请求内部仍使用 LangChain 重试，并由自适应反馈按失败类别调整输出预算、上下文、思考模式和超时。

## 3. 当前两种执行模式

### 默认研究模式

1. CLI 初始化研究编号与 SQLite 检查点；`initialize_research` 确认模型版本、阅读配方和工作流版本。
2. `route` 生成多源计划、任务类型及完整新闻查询指令：查询组、人物、机构、主题、时间、栏目、指定来源、排序、覆盖和数量。
3. `recall_memory` 在选择新闻源且时间计划有效时召回已读新闻；它先于在线收集，不与整个在线阶段同时启动。
4. `collect_sources` 并行执行选中的三个来源，稳定合并结果；在线新闻优先于同 ID 的旧记忆。
5. `grade_documents` 在精读前筛相关性，返回保留/排除/待确认及理由；仅明确排除才移除，解析失败暂存并显示。判断相关性不要求文章已写出未来答案。
6. `read_documents` 只为通过或待确认的新闻建立分段任务，复用已完成成果；随后 `assess_evidence` 检查充分性和风险。缺口有预算时补搜，再回到筛选。方法和网页摘要不走新闻精读任务。
7. `dispatch_specialists` 为分析/预测问题创建专题任务。事实型问题或没有入选证据时跳过；专题可受限回读并建议补搜。
8. `generate` 创建或复用候选答案；`evaluate_generation` 检查依据和任务完成度，选择结束、补搜或重写。

![研究模式：多源工具、阅读复用、专题回读和有界修正](agentic-rag-research-flow.svg)

图把“先筛选、后精读”合并为一个阶段，“充分性、专题”合并为另一个阶段；不是节点一一对应图。精确边表见[代码事实参考](reference.md)。补搜不重跑初始路由或记忆召回，也不改写原问题。

### 基础模式

设置 `RESEARCH_ENABLED=false` 后，跳过研究初始化、长期记忆、分段阅读与专题任务。仍保留多源并行工具检索、相关性/充分性检查、补搜、生成和评审。

![基础模式：受控检索、证据评估、补搜与重写](agentic-rag-core-architecture.svg)

基础模式不等于完全不落盘。CLI 仍接入检查点、运行记录；新闻向量缓存与答案缓存分别受自身开关控制。直接调用 `build_graph()` 不会自动注入检查点，需调用方传入 `checkpointer`；默认 CLI 已处理。

## 4. 状态为什么要分开存

`GraphState` 是 `TypedDict(total=False)`，不是运行时校验器；节点返回局部更新，由图合并。

| 字段组 | 例子 | 目的 |
|---|---|---|
| 用户目标 | `question`、`original_question` | 补搜词不替换原问题 |
| 执行计划 | `selected_sources`、`source_queries`、`news_search_plan` | 保存实际查询与日期决策 |
| 研究身份 | `run_id`、`model_revision`、`reading_recipe`、`workflow_revision` | 防止混用不兼容状态 |
| 证据 | `documents`、`answer_documents`、`evidence_context` | 区分候选、入选文档、实际送入模型的片段 |
| 任务成果 | `reading_reports`、`specialist_findings` | 覆盖率、引用、专题结论与限制 |
| 控制 | `retries`、`answer_revisions`、`query_history`、`no_progress_rounds` | 限制循环 |
| 输出 | `generation`、`answer_review`、`generation_grounded`、`generation_complete` | 区分有文字与通过核验 |

`document_grades` 保存结构化判断及理由，笔记保留原材料筛选键，避免补搜后反复评估同一材料；不确定结果下轮重查。研究模式按问题、评估片段、筛选规则和模型/思考设置写 SQLite 缓存。旧布尔缓存不再复用，它不是对文章永远有效的标签。

## 5. 路由与日期：模型建议，代码约束

路由可同时选择知识、新闻、网络，每个来源有独立查询；没有选择时兜底公开搜索。数据源描述说明能力边界，不证明库里一定有某篇新闻。

新闻查询是模型生成、Schema 校验、程序执行的结构化指令。多组短字面查询合并候选；规划要求每个非空人物/机构/主题类别至少有一个代表词进入查询，否则反馈重做，但不保证所有标签均被查询或同时出现在每篇结果中。指定来源、精确时间和栏目在结果层过滤；排序可选相关性、最新或最早，覆盖标签只约束规划中的正文预算目标，不截断候选。私有库不能保证收录任意外部媒体，指定这类来源时还会加入公开搜索。来源匹配采用名称/URL 别名和子串，不是媒体身份认证；语义排序不能找回字面查询或硬条件排除的文章。

时间模式：`unrestricted` 不带边界；`suggested` 是有理由的模型建议；`explicit` 表示模型识别到用户明确条件。自然日使用 `start/end`；“过去24小时”等相对窗口必须基于当前上海时间生成带时区的 `published_after/published_before`。API 用对应自然日粗筛，程序再按时间戳过滤，历史记忆也使用同一规则。无效的显式条件停止查询，不能悄悄放宽。**“用户明确时间”仍是模型识别结果**，不是独立自然语言日期解析器。

## 6. 三类检索、四项取证与四项规则工具

四项取证工具取得知识、新闻、网页摘要和本地原文；`tools/guardrails.py` 的四项规则工具负责输出结构、重试决策、概率证据与概率答案校验。规则工具不调用另一个模型，也不生成新事实；取证路径如下。

### 本地知识

`search_knowledge` → `ensure_index` → Retriever → Chroma。只在集合为空时自动初建；已有非空索引不会因重启 CLI 自动扫描文件变化。监听关闭时，资料变动后运行一次增量同步。

`knowledge/` 是给模型检索的材料，`docs/` 是给人看的说明。嵌入模型由配置指定，仓库默认不等于用户当前本机设置。`lru_cache(maxsize=1)` 只避免同一进程重复加载，不是跨进程缓存。

### 新闻

`search_news` → 结构化查询校验 → API 字面词/自然日/栏目粗筛并取完所有摘要页 → 去重 → 精确时间与指定来源硬过滤 → 全部候选统一评分、完整留档 → 按相关性/最新/最早排序及正文预算选择 → LangChain `Runnable.batch` 并发获取入选正文。标题/摘要向量缓存不保存全文。

每页最多 20 条，每组查询都持续到 `has_more=false`；移除旧的 30/100 条候选上限和查询组配额。向量增量写入每批32条，语义查询每批256条覆盖全部有效候选；只嵌入一次查询。评分采用 70% 语义相似度、20% scikit-learn 稀疏字符 TF-IDF、10% 查询组覆盖率；向量失败时全体统一改为 90% TF-IDF、10% 覆盖率，不能让先成功的一批占优。标题在词法文本中双计权；同分依次按时间、稳定标识排序。权重是阅读优先级，不是热度或可信度。相关性模式还保留查询组覆盖；显式时间排序优先于分数。

所有候选的标题、摘要、元数据、分数分量、系数与选择状态通过 artifact 返回，每50条一批写入 `news_candidates` 事件。终端显示总量、暂未精读量和入选正文的权重/原因；模型只接收有界预览与检索覆盖说明，不将所有候选视为已读证据。**多组字面查询当前依次执行**，不能把多来源并发说成所有关键词也并发。无关键词、无时间范围的查询可能遍历整个可访问归档，时间和索引开销会增加；全分页也不等于已召回库外或字面查询未命中的新闻。

API 部分失败保留成功结果并标记 `retrieval_complete=false`，不宣称候选收齐；完全失败且没有时间/来源限制时尝试旧候选缓存，有这些限制时不走无法保证过滤条件的回退。正文失败降级为摘要并报告警告，与分页完整性分别记录。两阶段检索限制正文开销，不保证高召回率。

### 公开网络与回读

`search_web` 返回标题、网址和摘要；保留服务日期或摘要开头日期为「未核实的日期线索」，不伪装成确认的发布时间。网络失败明确报错，正常无结果才是零条。

`read_news` 使用程序注入的当前 E 编号白名单读取本地保存版本，不重新请求远端、不接受任意路径。它按关键词选取有限原文片段，不是再次精读全文。一专题最多回读一轮；输入和字符上限见[工具说明](tools-guide.md)。

## 7. 存储、复用和并发

知识索引、新闻候选缓存、研究事实库、阅读/专题投影、答案缓存、检查点分别维护。SQLite 保存权威记录，Chroma 保存可重建投影；版本键见[研究指南](research-memory-guide.md)。

阅读复用依赖文章身份、内容版本和阅读配方；专题复用依赖目标、问题、实际证据、模型/规则版本等严格任务键。语义近似只用于召回，不直接证明已分析过。

来源收集和持久化研究任务使用各自的有限线程池；正文获取与独立文档评分使用 LangChain `Runnable.batch`，分别受 `IO_CONCURRENCY` 和 `LLM_CONCURRENCY` 限制。模型与网络另有进程内槽位。任务有原子领取、续租、重试和过期执行者提交保护。线程并发不保证 GPU 内部并行；Ollama 还要配置足够的 `OLLAMA_NUM_PARALLEL` 槽位，两个 CLI 进程也不共享模型信号量。显存允许时可用 Flash Attention 和量化 KV cache 降低并行上下文开销，实际是否生效应以 runner 参数为准。

`RESEARCH_TIMEOUT` 是每批调度预算，不是整次研究墙钟上限。取消是协作式，已发 HTTP 请求可能等待自身超时。当前控制成果提交，不保证外部模型调用严格 exactly-once。

## 8. 证据、生成与反思

模型资源策略按输出契约分层：短结构化决策和摘录节点使用较小首轮生成预算并关闭深度思考；证据综合、专题分析与最终回答保留全局思考设置。常规输出、上下文与超时配置决定首轮资源，`LLM_ADAPTIVE_*` 配置才是动态调整硬上限；自适应工具只在观测到截断、格式、超时或连接故障后给出有界调整，不会为每次短调用预先占满额度。

证据按正文、文章 ID、规范化长标题等去重，再判相关性。单篇相关不等于整批充分；方法文档能提供框架，不能替代最新事实。

上下文选择在来源和检索轮次间交错，长文按查询抽取片段；预算按字符而非精确 token。E 编号绑定当次入选列表，生成与评审共享 `evidence_context`，不能将 E 编号当永久文章编号。

预测允许“当前事实 + 明确假设 → 条件判断”，不要求已有未来答案。应区分事实、机构预测与自身推断，给驱动、情景、限制和跟踪指标。

概率题另外记录 `estimate_kind`、`target_event` 和 `forecast_horizon`。涉及政策利率时强制规划知识、新闻、公开搜索；直接概率证据不足且有本地新闻版本时，先定向回读再考虑补搜。生成前规则查数值、方法和非摘要证据；交付前查事件、年份、数据时点、概率值、方法和 E 引用。当前是关键词/类型/格式的确定性检查，不是利率期货计算器；不能证明出现的百分比确实属于目标事件，也不能保证季度内事件与单次会议概率口径一致。

评审同时检查 `grounded` 与 `answers_question`，并逐项返回 C 编号风险的处理情况与说明。预测有时间、口径、反向证据、价格基准、因果传导五类必核义务，评估器可追加具体风险。因果核验要求解释事实如何影响预测对象：个体保险/套保不能直接证明市场价格更稳定，现货品质分层也不等于标准化期货合约分层。`evidence_audit.py` 拦截遗漏/重复/未解决项目及明确自相矛盾的回应；代码还查动作冲突、无效 E 编号及不必要拒答。语义判断仍可能错误，通过不等于预测正确。

研究补搜用 `RESEARCH_MAX_ROUNDS`，基础补搜用 `MAX_RETRIES`；重写共用 `MAX_ANSWER_REVISIONS`。重复查询、连续无新增和任务预算也限制扩张。停止补搜后仍可尝试有限证据回答，最终失败明确说明。

## 9. 三种增量更新

1. **知识文件**：SHA-256 清单记录块 ID；未变跳过，修改先删旧块再写新块，删除文件清掉对应向量。签名含切块、模型、集合；变化或显式 `--rebuild` 触发重建。不是原子切换，监听是轮询。
2. **新闻候选**：稳定文章 ID + 内容/元数据指纹，批量 upsert；相同候选不重复嵌入。模型不匹配时报错，不能混用向量空间。
3. **阅读记忆**：新正文生成新版本，相同片段/配方可复用。阅读成果与向量待办事务提交；投影失败可修复，无需重做阅读。

更换嵌入模型需遵循各索引规则；同路径原地替换权重不会自动产生新配置身份，应使用版本化名称/路径。本次文档更新不改变知识文件或索引格式，不需重建。

## 10. 答案缓存与恢复不是一回事

答案缓存绑定问题、证据、模型名、提示版本、日期、实际上下文、专题成果及研究模型版本等信息；只缓存最终核验通过且有证据的答案。**命中后仍进入评审**，TTL 见[参考](reference.md)。

`--resume` 从检查点继续，完成研究展示保存结果，不刷新新闻。未完成研究的模型、阅读配方或工作流版本变化时拒绝混用。新问题仍能复用兼容阅读成果。下一次提问是新研究，检查点不等于跨问题聊天记忆。

恢复状态不能只看 `snapshot.next`：节点结果写入与下一检查点提交之间可能出现 `next=()`、`tasks` 仍带结果。`research/inspection.py` 的 `has_pending_work` 同时判断两者；只有没有待推进任务且有保存答案才走“展示结果”分支。对应真实 SQLite 边界回归验证恢复不重跑已保存的路由调用。

## 11. 连接、安全与缺口

本机 Ollama 回环地址不继承系统代理，远程地址仍遵循环境配置。503 不能单凭状态码断定是加载问题；先用[运行指南](operations.md)定位连接、模型和请求阶段。

`checked_structured/checked_text` 先进行有界自适应：429、5xx、超时、连接、空输出、格式和截断分开处理，4xx 客户端错误与未知错误不盲目扩容；完整响应再经 `validate_model_output`。适应次数取 `LLM_MAX_ATTEMPTS` 与 `LLM_ADAPTIVE_MAX_ATTEMPTS` 的较小值。外层 `_with_model_retry` 仍是 LangChain 传输重试包装，内层已处理的传输失败包装为 `ModelAdaptiveRetryError` 后不会再次触发外层同类重试。

子任务调度器的失败分类仍不完整：它仅对输出截断持久标记为不自动重试，其他失败可能进入 `TASK_MAX_ATTEMPTS`。因此不能把单次模型链的错误分类说成整个研究已做到所有永久错误只执行一次。动态上限由调用时的当前值与配置共同约束；将 adaptive 值设得比首轮值更小，不会追溯压低首轮请求。

新闻密钥放认证头、拒绝不安全远程 HTTP、禁止地址内嵌凭证、限制分页与 cursor。工具隐藏运行上下文并限制回读范围；这不是多租户鉴权。原文、问题和结果存于本机，应按私有数据保护。

已确认未解决：阅读数字子串/单位校验偏弱；专题摘要长度主要靠提示；记忆没有完整可信审核流；有限候选后过滤日期可能漏召回；评估上下文不等于生成上下文。详见[当前边界](status.md)，不要把建议写成已实现。

## 12. 怎样展示与验证

先用 `agentic-rag --list-tools` 展示契约，再观察查询、日期、任务、复用、工具事件、E 引用和反思。展示失败与恢复比只展示漂亮答案更能说明工程能力。

Token 计量在 `token_usage.py`：CLI 为每次执行创建 `UsageLedger`；`meter_node` 包装图节点，为重复执行的步骤分配独立编号；统一 `_with_model_retry` 在每次尝试里挂 `UsageCallback`，从模型回调读取原始计数，早于结构化输出/字符串解析。因此“模型成功返回、解析失败”的消耗不会丢失。

研究调度线程通过 `copy_context()` 继承账本和步骤，另标任务 ID/尝试号；事件先落盘再入队，图的 custom 流唤醒主线程显示，避免并发打印串行错位。账本用锁保护、以调用 ID 去重重放；`--status` 查询全量 token 事件，不截成最近 100 条。统计接线不改变图状态与模型提示，因此不用重建向量库或使旧阅读任务失效。具体输入/生成/未知值口径见[运行指南](operations.md#token-统计怎么看)。

同一账本保存计时事件：`meter_node` 用单调时钟记录每次节点的实际经过时间，`usage_session` 在正常/异常/中断退出时保存本次执行耗时。按 session ID 去重重放，恢复间隔不计入累计；旧数据无计时则标未知。模型请求已有独立时长，多个线程的请求耗时之和可能大于墙钟总时长，两者分开展示。预热单独计时，程序总账只接收本进程新事件。此次计时改动没有更改提示词、缓存版本、日期条件或已保存的研究内容。

终端展示与计量分离：默认 `console.py` 显示步骤数字、查询条件、工具计划/调用者/理由、入选权重、进度和异常，`-v` 展开完整参数、证据判断和逐调用用量。`--status` 用只读检查点与完整账本生成诊断摘要，`-v` 输出完整 JSON；工具计数包含确定性规则调用，不能直接当作外部取证次数。中断时计划不冒充执行、取回候选不冒充已读全文。

CLI 输入空闲退出默认 300 秒，只计等待新问题的时间，不中断正在运行的研究。退出路径尝试通过空请求和 `keep_alive=0` 卸载模型，不等于强杀 Ollama 进程；共享服务上的其他调用也应纳入使用考虑。

回归：`python -m pytest -q`；文档核对：`python scripts/docs_sync.py --check`。离线测试不证明真实新闻覆盖、GPU 吞吐或预测准确率。RAGAS 有数据域和取样问题，见[评估说明](evaluation_ragas.md)。

阅读顺序：CLI → 主图与状态 → 节点 → 工具执行器 → 研究服务 → 调度器 → 存储/记忆 → 对应测试。
