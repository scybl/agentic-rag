# 检索竞技场：实现、实验与失败边界

本文是离线检索实验平台的使用与验证说明，建立在[实验基线与 Trace](实验基线与Trace.md)之上。它没有替换默认研究流程，也没有网页前端。

已实测 SQLite FTS5/BM25、本地 BGE Dense、RRF、MMR、ranx 指标与配对检验。CrossEncoder 的进程隔离、缓存、错误和超时降级已有实现与测试，**本机尚未安装专用重排模型，没有其真实质量或推理速度结果**。`agentic` 完整研究适配器、真实财经金标准和端到端答案评测仍未完成，不能把第二阶段描述为已证明所有组件有效。

## 1. 为什么值得做

要回答的不是“用了几种算法”，而是：

- 同一道题，关键词检索、语义检索和融合分别找到了什么？
- 文档为何从第 5 名变成第 2 名？是哪一阶段改变的？
- 增加一个模型后，排序是否更好，失败和耗时是否增加？
- 全部检索失败时，评估是否仍保留这些问题？

这里复用成熟实现：SQLite 计算 BM25，Sentence Transformers 加载模型，ranx 计算指标及检验。自研部分是中文分词适配、实验契约、候选编排、排名轨迹、故障隔离、模型指纹和可比较性校验。RRF/MMR 是小型确定性编排函数，不是自研模型或向量数据库。

## 2. 五个适配器的准确含义

| `--adapter` | 当前执行内容 | 依赖 |
|---|---|---|
| `current_tfidf` | 复用生产代码的无向量 TF-IDF 降级排序；全部冻结材料作为候选 | 项目基础依赖 |
| `bm25` | FTS5 词法召回，未匹配材料不返回 | Python SQLite 的 FTS5 支持 |
| `dense` | 全量材料向量的精确余弦排序 | 已下载的本地嵌入模型 |
| `hybrid` | BM25 和 Dense 各取候选，再做 RRF | 本地嵌入模型 |
| `rerank` | 对 RRF 排名前 N 项执行 CrossEncoder，失败保留融合排名 | 本地嵌入模型及专用重排模型 |

`--mmr` 是第二至第五种适配器的可选末级处理，不是另一种召回器。对 BM25 启用它也需要本地嵌入模型，以计算文档间冗余。

所有新适配器都只索引**标题 + 摘要**，不读取正文，也没有日期/实体硬过滤。这是固定候选材料实验，不是新闻 API 全库召回、chunk 检索或完整研究对照。生产新闻链路原有的过滤、正文读取和预算不受影响。

### 2.1 BM25：保留词频，统一分数方向

中文连续文本被切成重叠双字词，英文和数字切成小写词；单字保留。文档词频不能去重，否则 BM25 的词频信息会丢失。查询词去重后最多使用 64 个，组成 OR 匹配表达式；字符白名单与参数绑定避免用户输入被执行为 FTS 运算符。

FTS5 的 BM25 分数越小越好，适配器取负号统一成越大越好。标题权重 2、摘要权重 1，ID 不参与匹配。空查询或完全无匹配返回空结果，不用任意文档补满。参见 [SQLite FTS5 BM25 说明](https://sqlite.org/fts5.html#the_bm25_function)。

双字词是透明的工程基线，不等于语义分词，也可能错过跨字词、代码和别名。应通过实体、数字和词法无命中案例检验，再决定是否需要 jieba 或专门财经词典。

### 2.2 Dense：小语料采用精确矩阵，而非 ANN

SentenceTransformer 只从指定本地目录加载，不自动下载、不执行远程自定义代码；当前固定 CPU。语料向量和查询向量归一化后计算点积，并验证维度、零向量和非有限数值。同分按文档 ID 排序，避免不稳定的并列顺序。

查询前缀默认使用中文 BGE 检索提示，不拼到文档上；换模型必须检查其训练约定，并用 `--query-prefix` 显式配置。BGE 模型说明见[官方模型卡](https://huggingface.co/BAAI/bge-small-zh-v1.5)。当前模型名称不代表所有模型都应使用同一前缀。

全量矩阵避免把 ANN 近似误差混入模型对照，适合当前 11 篇材料；不是大规模数据库选型结论。`index_vector_bytes` 只记录 NumPy 文档向量矩阵大小，不是进程峰值内存，也不包括模型权重、FTS 索引和中间张量。

### 2.3 RRF：融合名次，不混加不同尺度的分数

每路候选对文档的贡献为 `1 / (c + rank)`，缺失项贡献零，默认 `c=60`。BM25/Dense 分别最多返回 `candidate_k=100` 项，融合保留并集，理论上最多 200 项。不会把 BM25 原始分数和余弦分数直接相加。

RRF 强调多路共同支持，但也可能把词法干扰放大。因此 `hybrid` 不保证优于 `dense`，本轮小样本已经出现这样的反例。

### 2.4 CrossEncoder：限定重排范围，超时终止进程

仅重排融合结果前 `rerank_k=80` 项，其余保留融合顺序；候选少于 N 时处理实际候选。模型同时读取 query 和材料，而非复用两个独立向量。[CrossEncoder 文档](https://www.sbert.net/docs/cross_encoder/usage/usage.html)说明了这种两阶段检索用法。

加载前要求配置声明序列分类架构，防止把嵌入模型当成未训练的分类头。此检查不能证明权重质量、标签方向或训练适配性，下载专用模型后仍必须用已知相关/不相关对验证分数方向。

独立 `spawn` 子进程负责加载和预测，期限覆盖启动、加载和推理；超时终止并回收该子进程。不是超时后仍在后台计算的线程。成功结果以“模型内容指纹 + query + 输入材料”缓存，失败不缓存。每次未命中缓存会重新启动和加载模型，这是可终止性换取的开销，当前不是常驻高吞吐服务。

模型不可用、超时、异常或非法分数会回退到完整 RRF 顺序，记录 `fallbacks`，运行终端显示降级次数。进程异常只保存类型，不泄露错误正文。运行完成与重排成功是两个不同事实。

### 2.5 MMR：展示相关性和多样性的交换

先把输入名次转换为线性相关度：第一名为 1、最后一名为 0。每次选择最大化以下效用的候选：

```text
lambda × 排名相关度 − (1 − lambda) × 与已选文档的最大余弦冗余
```

冗余截断到 0–1，默认 `lambda=0.7`。选出前 Top-k 后，其余材料保持原有顺序。MMR 在本项目是“基于排名的相关度版本”，不能把原始 CrossEncoder 分数当成它的最终效用。

候选 `score` 仍是前一阶段分数；`rank_history` 中 MMR 的分数也只是该分数，不伪造效用分。最终顺序以 `rank` 为准，指标程序使用 `1/rank` 作为代理分数，防止 ranx 再按旧分数重排。现有实现减少语义冗余，不保证来源、时间、相反观点或风险义务覆盖；后者属于上下文编译阶段。

## 3. 怎么运行

在项目根目录，使用已安装本项目的环境。评分的可选依赖独立安装：

```text
python -m pip install -e ".[retrieval-eval]"
python -m agentic_rag.evaluation run evaluation/suites/finance_smoke_v1/suite.json --adapter bm25 --split all --repeat 2 --output evaluation/runs/demo-bm25
python -m agentic_rag.evaluation run evaluation/suites/finance_smoke_v1/suite.json --adapter dense --embedding-model .models/bge-small-zh-v1.5 --split all --repeat 2 --output evaluation/runs/demo-dense
python -m agentic_rag.evaluation run evaluation/suites/finance_smoke_v1/suite.json --adapter hybrid --embedding-model .models/bge-small-zh-v1.5 --split all --repeat 2 --output evaluation/runs/demo-hybrid
python -m agentic_rag.evaluation run evaluation/suites/finance_smoke_v1/suite.json --adapter hybrid --mmr --embedding-model .models/bge-small-zh-v1.5 --split all --repeat 2 --output evaluation/runs/demo-mmr
```

目录必须不存在，重复执行请换名字。默认仍只跑 dev；示例 `--split all` 只用于合成工程回归，正式调参不能反复窥视 test。

准备好专用重排模型后才使用下面命令；`YOUR_RERANKER_DIRECTORY` 是需替换的本地目录，不是仓库自带模型：

```text
python -m agentic_rag.evaluation run evaluation/suites/finance_smoke_v1/suite.json --adapter rerank --embedding-model .models/bge-small-zh-v1.5 --reranker-model YOUR_RERANKER_DIRECTORY --reranker-timeout 60 --split all --repeat 2 --output evaluation/runs/demo-rerank
```

单次评分和配对检验：

```text
python -m agentic_rag.evaluation score evaluation/runs/demo-bm25 --k 1 --k 4 --output evaluation/reports/demo-bm25.json
python -m agentic_rag.evaluation score evaluation/runs/demo-bm25 --against evaluation/runs/demo-hybrid --k 4 --allow-change adapter --allow-change embedding_model --output evaluation/reports/demo-bm25-vs-hybrid.json
python -m agentic_rag.evaluation score evaluation/runs/demo-hybrid --against evaluation/runs/demo-mmr --k 4 --allow-change mmr --output evaluation/reports/demo-hybrid-vs-mmr.json
```

`--allow-change` 不是跳过全部校验；只放行列出的实验变量，仍要求语料、标签、划分、样本数和重复数一致。不同代码、环境或模型文件默认拒绝比较。原来的 `compare` 只比较行为/排名，`score --against` 才调用 ranx 检验。

Numba 的首次评分会编译，比后续慢。Windows 安装目录可能不可写，程序默认把 Numba、数据集库和绘图库缓存定向到临时目录，不下载评测数据；Numba 写入前用一次独占创建检查权限，避免缓慢反复探测。若显式设置 `NUMBA_CACHE_DIR`，会尊重该路径，需确保它可写。

## 4. 评分口径与统计陷阱

使用 [ranx evaluate](https://amenra.github.io/ranx/evaluate/) 的 Precision@K、Recall@K、MRR@K、nDCG@K；graded qrels 使用原有 0–3 标注，正相关门槛为 1。报告保留每题、每次运行和题型分桶。指标针对保存的完整候选顺序，K 可以大于生成阶段的 Top-k；这不表示那些材料都被送给了生成模型。

- 每题先平均重复运行，再按独立问题宏平均。10 题跑 2 次仍是 10 题，不是 20 个独立样本。
- 执行失败和零命中的可评分问题按空排名参与评分，不从分母消失。专门处理 ranx 字典构造器的全空输入边界，使用公开空 Run 接口补齐问题，不制造占位文档。
- 没有任何正相关 qrel 的问题单列为排除项，不能计算有意义的 Recall/nDCG；仍在运行失败/降级统计里。这些样本的拒答正确性尚未评估。
- 若所有题都无正例，指标为 null，不报告 0 或 100% 作为质量结论。
- 先验证所有产物及 Trace，再评分。报告记录 ranx 版本、评分源码指纹、指标协议、输入套件和被评分实现身份。
- 两个运行使用 [ranx compare](https://amenra.github.io/ranx/compare/) 的 Fisher 随机化检验，1000 次置换、种子 42，以问题为独立单位。
- 重复间排名或成功/失败状态波动时，只报告逐题平均分，不拿第一轮冒充均值做检验。独立可评分问题少于 2 个也不做检验。
- 多指标 p 值未作多重比较校正，仅作探索；不能挑一个有利指标就宣称系统整体显著提升。检索相关性也不是答案准确率或投资收益。

## 5. 本轮真实验收记录（2026-09-30）

运行条件：`finance_smoke_v1`，11 篇虚构材料、10 题、每题 2 次；其中 1 题无正相关标注，检索指标的独立分母为 9。CPU、本地 `bge-small-zh-v1.5`、ranx 0.3.21。六组运行使用相同源码指纹 `3bf075c13191da74b2be0fba7dd6e8f5ef8715aca677f319b2a6bf58ab27de2b`。

| 方案 | Recall@4 | MRR@4 | nDCG@4 | 查询观测中位耗时 | 失败 / 降级 |
|---|---:|---:|---:|---:|---:|
| 当前 TF-IDF 基线 | 1.0000 | 0.8889 | 0.9113 | 1.991 ms | 0 / 0 |
| BM25 | 0.9444 | 0.8704 | 0.8846 | 0.156 ms | 0 / 0 |
| Dense | 1.0000 | 0.9444 | 0.9590 | 6.829 ms | 0 / 0 |
| BM25 + Dense + RRF | 1.0000 | 0.9444 | 0.9535 | 7.086 ms | 0 / 0 |
| 上述融合 + MMR | 1.0000 | 0.9444 | 0.9397 | 7.422 ms | 0 / 0 |
| 缺失重排模型的降级演练 | 1.0000 | 0.9444 | 0.9535 | 7.215 ms | 0 / 20 |

这不是性能基准：六组在同一进程依次运行，库/文件缓存状态不同；查询中位数不含一次性模型准备，也未随机交错或统计延迟区间。Dense 首组准备耗时 4.637 秒，后续复用系统缓存后的模型组约 0.23 秒，不能据此说混合索引构建更快。文档向量矩阵 45,056 字节，不等于模型只用 44 KiB 内存。嵌入/重排 Token 未计量，保持未知，不能解释成全流程零成本。

本机产物保存于 `evaluation/runs/phase2-verified-{tfidf,bm25,dense,hybrid,mmr,fallback}`，评分和比较报告在 `evaluation/reports/phase2-verified-*.json`；目录默认不提交。每份清单包含唯一实验 ID 和模型内容哈希，可追溯实际文件，而非只记录模型名。

可以得出的结论：

1. 模型实跑、排名链路、失败保留和指标计算可用；每个候选能回查各阶段名次。
2. MMR 在这批题上改变了排序，却没有提高 Recall@4；nDCG@4 下降，说明多样性不自动等于本题相关性。
3. BM25 对混合的 nDCG@4 检验 p=0.488；混合对 MMR 为 p=0.233，均不足以按 0.05 阈值声称差异显著。9 个合成可评分问题更不能证明领域收益。
4. 降级组和融合组指标相同，是回退保序的证据，**不是 CrossEncoder 有效性的证据**。

下一步应先扩大并人工复核实体、时间、数值、同主题重复和反向证据案例，再决定默认是否启用重排/MMR。尚无证据支持此时增加 BGE-M3、ColBERT 或 Contextual Retrieval，它们仍是设计中的可选研究路线。
