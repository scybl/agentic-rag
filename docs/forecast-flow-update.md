# 预测流程优化说明

本文前半部分描述当前流程，末尾保留早期改造实测，不能将历史测试数视为最新版。完整架构见[技术详解](技术细节详解.md)，参数以[代码事实参考](reference.md)为准。

## 为什么原来的答案会拒绝预测

原流程倾向于“资料里有什么，就回答什么”。这适合核对事实，但对预测不够：预测本来就是在既有事实之上，借助因果逻辑和假设推导未来情景。

单篇新闻相关，不代表整批证据覆盖了预测因素；回答没有虚构事实，也不代表完成了用户要求。因此本次同时调整了检索、生成与反思，并保留真正证据不足时的诚实退出。

## 从代码哪里开始读

1. `src/agentic_rag/graph/build.py`：先看节点连接。原来的“没有文档才重试”改为“检查证据缺口，再选择补搜或生成”。
2. `src/agentic_rag/graph/chains.py`：看 `SourcePlan`、`EvidenceAssessment`、`AnswerAssessment`，它们是模型必须返回的数据结构；随后读三个对应提示词和生成提示词。
3. `src/agentic_rag/graph/nodes.py`：依次读 `assess_evidence`、`supplement_sources`、`generate`、`evaluate_generation`、`revise_answer`。模型建议动作，程序负责预算、分支、一致性和引用编号检查。
4. `src/agentic_rag/news_retrieval.py`：看多组关键词全分页、候选去重、完整留档、加权排序与主题覆盖。API 仍按字面关键词召回，不会把不同主题放在一个长句里同时要求匹配。
5. `src/agentic_rag/evidence.py`：看相关原文选段、证据去重、`[E1]` 编号。生成与核验使用同一份证据片段。
6. `tests/test_forecast_flow.py` 与 `tests/test_generation_check.py`：看如何不用真实模型验证闭环，以及如何模拟“模型错误地判定通过”。

## 现在每一步会做什么

| 阶段 | 检查的问题 | 后续动作 |
|---|---|---|
| 规划 | 是查事实、解释影响，还是预测？需要什么因素？ | 为不同来源生成具体查询 |
| 取证 | 哪些资料需要抓取、哪些新闻已经读过？ | 工具取证，保留来源与原文 |
| 模型输出与恢复契约 | 返回是否符合目标类型？是否截断、超时、空输出或服务故障？ | 格式错则反馈字段原因；资源失败则在硬上限内扩容、延时、关闭思考、切分或停止 |
| 相关性筛选 | 单篇有实质事实或适用方法？是否同名异物？ | 保留/排除/待确认及理由，解析失败不删除 |
| 新闻精读 | 相关/待确认新闻哪些片段需处理？ | 短文原样保留并明确0次阅读模型调用；长文先去重再每段最多六项，截断可二分一次；下游按问题补回完整原文句子 |
| 整批证据检查 | 价格基准、关键驱动等是否足以条件分析？ | 缺关键事实就补查；有依据就生成 |
| 专题研究 | 各核对因素之间有何条件、冲突和缺口？ | 默认研究模式派发专题任务，可受限回读，必要时补搜 |
| 生成 | 已知什么、假设什么、会出现哪些情景？ | 写方向、驱动、三种情景、限制与跟踪指标 |
| 反思 | 依据可靠吗？真正完成用户任务了吗？ | 接受、补事实或重写答案 |
| 程序校验 | 时间、口径、反向证据、基准、因果传导风险是否全部回应？引用是否存在？ | 拦截遗漏/重复/未解决风险、冲突标记和不必要拒答 |
| 概率证据契约 | 是否有概率数值、估算方法和非搜索摘要的可追溯正文？ | 优先定向回读已有版本，仍不足且有预算则补搜；不能越过预算或用宏观观点代替概率数据 |
| 概率答案契约 | 是否重申事件和时点，并给出0–100%的数值/区间、方法和引用？ | 程序覆盖模型的错误 `accept`，补证据或重写 |

终端会显示任务类型、因素、实际关键词和日期、每组每页返回数、覆盖与缺口、补搜或重写要求、证据编号，以及两项核验结果。建议查询但本轮未执行时，会明确标注，避免把建议误当执行记录。

“概率”不是普通方向预测。路由模型即使误分为一般分析，程序也会根据“概率、几率、可能性、odds、probability”等明确措辞升级为概率估计，并强制使用公开检索寻找直接数据和方法。每个工具调用都会显示工具名、调用者、理由、参数摘要和结果；缺少调用者或理由的程序调用会在执行前被拒绝。

对于美联储、降息、加息和联邦基金相关概率题，程序还会强制加入本地方法检索、新闻检索和公开搜索。若已有新闻版本但提取结果没有概率数字或方法，先定向回读原文并重跑证据契约；只有原文仍不足时才提出新的新闻与网络查询。规划终端会对全部八个工具显示“必须、条件、跳过”及理由，其中模型输出校验始终必须、自适应重试按失败条件调用，避免只注册工具却没有可核对的调用路径。

这些检查不是概率估算算法。当前代码没有从期货合约价格计算隐含概率的专用数据接口/计算器，也没有自动校准模型；仅出现方法词和百分比可能误过规则，目标季度与单次会议仍可能口径不一致。方向预测可以给条件判断，数值概率必须有可核对依据，不能为了“完成预测”编造百分比。

## 默认预算与使用方式

- 每组新闻查询取完全部摘要页，每页最多 20 条；不再使用旧的 30 条总量预算，也不按查询组分配候选配额。所有匹配候选与权重留档，分页失败时注明未取完。
- 正文预算当前为1–100篇，明确数量由交付契约覆盖默认值；“最新N篇”先核对主题再建立有界集合，“影响最大”使用独立潜在影响评分。未明确数量仍保留全分页路径。见[研究指南](research-memory-guide.md)。
- 默认研究模式由 `RESEARCH_MAX_ROUNDS` 控制补搜，默认 3 轮；关闭研究模式后由 `MAX_RETRIES` 控制，默认 2 轮。重写由 `MAX_ANSWER_REVISIONS` 控制，默认 2 次，独立计数。重复查询、无进展、累计时间和模型调用预算也会提前限制补搜；阅读分段数量不再截断任务。
- 默认最多 9 条证据、6000 个证据字符，模型上下文 8192、最大输出 2048 token。证据字符预算不包含全部提示、问题和专题建议，不等于严格 token 总预算。环境变量可以覆盖。
- 仍没有固定日期窗口；模型建议与实际采用的日期继续在终端展示。
- 后台目录监听仍默认关闭。此次没有改知识文件、嵌入模型或索引格式，不需要重新构建知识库。
- 更新后先执行 `python -m pip install -e ".[dev]"` 安装新词法排序依赖，再重启 CLI。工作流/提示/阅读版本已经升级，不兼容的未完成研究需重新提问；不要清空历史记录。

## 历史记录：2026-09-29 预测流程初次改造

以下保留当时使用 conda `agent`、本地 `gemma4:26b` 和新闻接口的记录。之后已增加持久化研究和工具层；该历史记录不代表当前全部实现，后续苹果期货专项验证见下一节。

1. 完整执行“分析一下2027年猪肉价格走势”。第二轮验证中，四组查询是“生猪”“猪肉价格”“饲料成本”“生猪产能”，共读到 30 条原始候选、去重后 27 条、入选 5 条新闻。整个流程筛选后使用 7 条证据，输出了基准、上行、下行情景，并说明生猪价与猪肉批发/零售价的区别和中等偏低的置信程度。
2. 专项反思验证只提供三篇近期新闻，不提供 2027 年预测报告。故意给出“未提供2027年预测结果，因此无法分析”的回答。首次发现模型的通过标记与要求重写的文字相矛盾，随后增加明确动作、一致性检查和有条件的拒答保护规则。
3. 修正后再次运行专项测试，反思节点选择重写；一次重写生成了条件预测，再次核验通过。程序没有把“必须找到未来预测报告”作为前提。
4. 自动测试：`python -m pytest -q`，75 项通过，另有 3 个子测试通过。覆盖补搜保留旧证据、避免重复评估、不必要拒答、反思标记冲突、引用编号、缓存版本、多查询预算和失败处理。

这些验证表明流程能够支持条件预测，并拦截本次暴露的错误拒答；不是对预测准确率的统计评估。模型仍可能误解新闻、写错因果关系或自检漏判，尤其网络部分仍是搜索摘要而非全文。实际使用时应核对关键原文，不把模型的“核验通过”理解为专业研究或未来结果的保证。
