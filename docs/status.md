## 展示目标与新闻数据边界

新闻侧当前验收目标是“采集持续运行，有去重后的新资讯入库，可供研究使用”。2026-10-01 的只读服务器检查观察到近七天约每小时运行，9 月 25—27 日新增分别为 534、281、303 条，28—30 日分别为 2,223、2,235、2,053 条；这些是当时的历史入库计数，不是未来更新保证，也不是上游总发布量或完整率。

当时仅启用同花顺九个栏目。源码确认按文章身份、URL、正文和标题日期等键去重，重复命中不等于新增；已发现两个历史链接重复发生正文提取失败。“一页没有新增即跳过后续文章”的策略存在遗漏后续旧文的风险，但当前抽查不足以量化历史漏采。用户已接受展示项目的偶发遗漏，暂不扩展完整率治理或历史补采；长时间无新增和连续异常才值得继续诊断。本次没有修改采集服务，也没有新增监控自动化。

API 分页取完只是取完“当前数据库内符合条件的结果”，不证明采集器收齐全站，更不证明覆盖全网。服务器采集是外部数据服务，不要包装成本仓库中新增的自主学习 Agent。

## 适用边界

- 本地单用户展示项目，无网页前端、多租户权限、完整安全沙箱或分布式队列；跨问题会话已接入 CLI，但不是通用记忆平台。
- 工具为程序受控执行，不是自由 ReAct；公开网络只用搜索摘要，不能声称已读完整研报。
- 研究记忆只覆盖实际抓取/读过的新闻；API 条件召回与摘要向量排序可能漏掉关键文章。
- 限流是进程内的，GPU 是否真正并行取决于服务；外部模型计算不保证严格一次。
- 字符预算不是精确 token 预算；所有提示与专题建议的总长度还需治理。
- token 统计是观测，不是端到端硬预算；Ollama 未报告的思考/输出细分、服务失败和强杀时缺失用量不能还原。嵌入与独立评估脚本不包含在 CLI 对话模型统计中。
- 知识索引重建不是原子切换；监听跨进程无写锁；嵌入距离等有库默认依赖。
- 数据库、原文版本和事件没有自动归档清理；模型同名换权重可通过摘要区分，但嵌入同路径换权重需版本化配置。
- 现有评审会误判。通过核验、流程完整阅读、测试全绿，都不能证明预测准确或报道真实。
